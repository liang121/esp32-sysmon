# ESP32 Wi-Fi App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add touch-based Wi-Fi configuration to the ESP32 APPS page and keep Monitor connected when the Mac's LAN IP changes.

**Architecture:** The LVGL UI sends scan/connect requests to the existing main task through a FreeRTOS queue; the main task owns ESP-IDF Wi-Fi events and NVS writes. The Mac collector remains a LAN HTTP server; the device retains the Mac's `.local` name and re-resolves it after failed requests without treating that failure as a reason to change Wi-Fi.

**Tech Stack:** ESP-IDF 5.3+, LVGL 9, C, NVS, mDNS, the existing Node.js serial configurator.

**Spec:** `specs/2026-09-28-esp32-wifi-app-design.md`

## Global Constraints

- Modify the existing local `esp32-sysmon-source` Git repository on `dev/esp32-wifi-app` and make one final feature commit.
- Keep the Monitor card's position, dimensions, colors, icon drawing, touch behavior, and both Monitor pages unchanged.
- Do not show signal strength, store credentials in source, log passwords, add a cloud service, or change the NVS partition layout.
- Keep the serial configurator working as a recovery path; do not erase NVS during flashing.
- Use built-in LVGL keyboard and textarea; use built-in Source Han Sans SC 16 only on Wi-Fi settings screens.
- Build and test before pushing; redact SSIDs, hostnames, and other local details in public artifacts.
- On this Mac, put `/opt/homebrew/Caskroom/miniconda/base/bin` before the system Python when sourcing `$HOME/esp/esp-idf/export.sh`; the installed IDF environment is Python 3.12 while the default `python3` is 3.9.

## Review Focus

- A scan started with no saved Wi-Fi must finish and show networks instead of attempting to connect with an empty SSID (Task 2, device check).
- An incorrect password must leave the old NVS credentials intact and restore the prior connection (Task 2, device check).
- A Chinese SSID must display distinctly and be passed to ESP-IDF unchanged; unsupported glyphs get a hex fallback (Task 1 and Task 2, device check).
- A Mac HTTP error while Wi-Fi remains connected must keep the current SSID and trigger hostname re-resolution (Task 3, device check).
- Repeated tapping and page changes during scan or connection must not duplicate an operation or leak a password into labels or serial output (Task 1 and Task 2, device check).

### Task 1: Wi-Fi screens and input contract

**Files:**
- Modify: `firmware-idf/main/ui.h`
- Modify: `firmware-idf/main/ui.c`
- Modify: `firmware-idf/sdkconfig.defaults`

**Interfaces:**
- Produce `ui_wifi_request_t` with `SCAN` and `CONNECT` kinds, SSID byte length, raw SSID bytes, and password bytes. The UI sends requests through a bounded FreeRTOS queue; the main task reads through `bool ui_take_wifi_request(ui_wifi_request_t *out)`.
- Produce `ui_wifi_present(const ui_wifi_view_t *view)`. The view has current SSID, connection state, up to 12 scan rows, error text, and an operation-in-progress flag. It never contains a password.

- [ ] Add the request/view types to `ui.h`, and make the UI queue single-owner: callbacks enqueue, the main task dequeues. Reject a second request while a scan or connection is in progress; zero the temporary password buffer after the main task receives it.
- [ ] Add the Wi-Fi card beside the unchanged Monitor card. Add a Wi-Fi screen with current connection, scan rows, back/home control, masked textarea, LVGL `lv_keyboard`, and Connect action. Open networks skip password entry. Include a rescan action; do not render RSSI.
- [ ] Enable `CONFIG_LV_FONT_SOURCE_HAN_SANS_SC_16_CJK=y` in `sdkconfig.defaults`. Use that font on SSID labels only. Reconfigure the existing local build and verify the option is enabled in its generated `sdkconfig`; a fresh build must pick it up from defaults. Check a Chinese SSID on the device; when a glyph is missing, append the undecodable UTF-8 bytes as hexadecimal to preserve network identity.
- [ ] Build with `export PATH="/opt/homebrew/Caskroom/miniconda/base/bin:$PATH"; . "$HOME/esp/esp-idf/export.sh" >/dev/null; cd firmware-idf; idf.py build`. ### Task 2: Event-driven scan, connection, and NVS commit

**Files:**
- Modify: `firmware-idf/main/main.c`
- Modify: `firmware-idf/main/CMakeLists.txt` only if a focused Wi-Fi module is extracted

**Interfaces:**
- Consume `ui_take_wifi_request` on the main task. Publish state using `ui_wifi_present` after scan completion, Wi-Fi events, and IP acquisition. Maintain existing `ssid`, `pass`, `ssid2`, `pass2`, and `lastnet` NVS keys.

- [ ] Start the Wi-Fi STA subsystem even when `n_nets == 0`, without attempting to connect to an empty network. Handle `WIFI_EVENT_SCAN_DONE` from `esp_wifi_scan_start(..., false)` and copy at most 12 results for the UI; keep their raw SSID bytes for connection.
- [ ] On Connect, stage the selected credentials in RAM, disconnect, set the STA config with `WIFI_STORAGE_RAM`, and connect. Keep the previous saved configuration in RAM. Only after `IP_EVENT_STA_GOT_IP` succeeds, write the selected network as preferred in one NVS commit and retain the prior preferred network as the optional second network.
- [ ] On rejected credentials, disconnect event, or explicit connection failure, restore the previous STA configuration and report the reason to the UI. Never overwrite NVS on failure; never print the staged password. Distinguish user-requested disconnects from genuine connection failures so a transition cannot trigger accidental fallback.
- [ ] Rebuild. Then on the connected device verify: no-config scanning; successful protected-network connection; wrong-password rollback; open-network selection when available; repeated taps during an in-flight operation; Chinese SSID display and byte-exact connection. Capture only redacted status and do not include credentials in logs or commits.

### Task 3: Mac name re-resolution and Wi-Fi failover policy

**Files:**
- Modify: `firmware-idf/main/main.c`
- Modify: `README.md`

**Interfaces:**
- Keep the existing `host` and `port` NVS configuration contract. `fetch()` continues to poll `/api/now` and refresh requests continue to call `/api/ai/refresh`.

- [ ] Change the reconnect decision so only Wi-Fi join/disconnect failure can select the second saved network. A failed Mac fetch cannot change the SSID. - [ ] Keep the current data freshness indicator and add distinct user-visible states for Wi-Fi offline, Mac name unresolved, and Mac HTTP failure. Do not use a timing delay as a substitute for event ordering.
- [ ] Update README with the APP-page Wi-Fi flow and explain that the Mac `host` setting should be its `.local` name. Keep the serial command documented as a recovery route.
- [ ] Build, then verify on the device: use the `.local` host setting, observe a fresh mDNS resolution after a failed request, stop the local Mac collector temporarily and check that ESP remains on the same SSID, disconnect Wi-Fi and check recovery/fallback, and reopen Monitor and AI Usage to check data and refresh. Restore the collector afterward. Do not force a Mac DHCP renewal during an active session; report actual address-change testing separately if it occurs naturally.
