# ESP32 Wi-Fi 配置 App 与 Mac 自动重连设计

日期：2026-09-28

## 目标与范围

在 ESP32 的 `APPS` 首页增加 Wi-Fi 入口，让用户直接在触屏上查看连接状态、扫描附近网络、选择网络并输入密码。Mac 的局域网 IP 变化后，Monitor 应重新解析已配置的 `.local` 主机名并恢复取数。此设计针对当前 ESP32-S3 设备和现有 Mac Sysmon 服务；不接入 clawd tunnel，也不改变 Monitor 的图标、页面内容或取数协议。

验收重点：无需 USB 即可改连 Wi-Fi；密码错误不会覆盖已可用的配置；Mac 取数失败不会使设备跳到另一条其实无助于连接 Mac 的 Wi-Fi；包含中文的 SSID 可以辨认。Wi-Fi 列表不显示信号强弱。

## 已核对的现状

- `firmware-idf/main/ui.c` 使用 LVGL 9 和 800×480 触屏，`APPS` 页目前只有 Monitor 卡片。其现有三柱图标由代码绘制。本次在旁边增加独立 Wi-Fi 卡片，不修改原卡片。
- 当前构建已经启用 LVGL 的 `lv_keyboard` 和 `lv_textarea`。现有 Montserrat 字体主要覆盖拉丁文字；依赖中的 LVGL 已提供 Source Han Sans SC CJK 字体，可仅在 Wi-Fi 设置页启用。
- `firmware-idf/main/main.c` 只在 NVS 已有网络时启动 Wi-Fi，最多保存两组 SSID/密码；USB 串口是现有配置入口。设备按已配置的数字 IP 或 `.local` 名字解析 Mac，再通过局域网 HTTP 读取 `:8787/api/now`。
- 当前设备临时保存了 Mac 的数字 IP。HTTP 请求失败会清除已解析 IP，而连续 30 秒取不到 Mac 数据会触发另一条 Wi-Fi 的切换；这把 Mac 不可达和 Wi-Fi 断开混为一谈。

## 方案与取舍

选用设备触屏配网：APP 页的 Wi-Fi 卡片进入设置页，使用 LVGL 自带输入框和键盘输入密码。它沿用现有 UI 和 Wi-Fi/NVS 实现，不要求手机、临时热点或新增服务。手机扫码配网会减少触屏打字，但需要 ESP 同时管理热点、配网页面和手机连接，暂不引入。继续只靠 USB 配置虽改动最小，却不满足设备上改网的目标。

Mac 寻址继续使用已存在的 `.local` 主机名配置。对这台设备，在最终验证时把当前数字 IP 改回实际 Mac 主机名；固件和公开仓库不硬编码个人主机名。Mac 请求失败后继续尝试用 mDNS 获取新地址，同时保留上次成功解析的 IP，直到查到新地址或 Wi-Fi 本身断开；一次 mDNS 丢包不应让服务恢复后继续离线。Wi-Fi 切换只响应当前网络断开或加入失败，不再因 Mac HTTP 失败而触发。这个调整避免旧的第二网络反复抢占，同时保留最多两组已保存网络供真正的 Wi-Fi 故障回退。

本方案依赖设备与 Mac 所在网络允许 mDNS 流量和局域网 HTTP 连接；访客网络隔离或跨 VLAN 时不会靠改 IP 自动修复。连接问题在设备状态中区分“Wi-Fi 未连接”“Mac 名字未找到”“Mac HTTP 失败”，便于定位。

## 用户动线与界面

1. 开机进入 `APPS`。原 Monitor 卡片和三柱图标保持原尺寸、位置、颜色和行为；其右侧增加 Wi-Fi 卡片。即使尚无保存网络，两个入口也可点。
2. 点 Wi-Fi 卡片，看到当前 SSID 和“连接中 / 已连接 / 未连接”，以及扫描出的附近网络列表。列表显示 SSID 和是否需要密码，不显示 RSSI 数值或信号格。左上角可回 `APPS`。
3. 点受保护网络，出现密码输入框与 LVGL 内置键盘；密码默认遮挡，可显隐。开放网络跳过密码。提供重新扫描和返回。扫描结果保留原始 SSID 字节用于连接，显示层正确呈现本机常用的中文 SSID；未覆盖的字形用对应 UTF-8 字节的十六进制后缀表示，避免显示为空白并混淆不同网络。
4. 点连接后显示“连接中”。网络加入并取得 IP 才写入 NVS，并把新网络设为首选；旧首选网络可作为第二保存网络。密码错误或连接失败显示原因，恢复原网络配置，旧密码不被覆盖。敏感密码不出现在状态页和日志中。
5. 返回 Monitor 后，设备继续用 Mac 的 `.local` 名字解析当前 IP。Mac 离线或 mDNS 查询失败时 Monitor 显示对应错误，Wi-Fi 设置页仍可操作；Mac 恢复或换 IP 后继续尝试解析并恢复数据。

交互预览已在设计评审时提供；实际输入控件使用当前固件里的 LVGL 组件。

## 实现边界

- `firmware-idf/main/ui.c` / `ui.h`：增加 Wi-Fi 卡片、设置页、连接状态、扫描列表和输入控件；通过明确的请求/状态接口与网络逻辑通信。Monitor 相关绘制函数不改。
- `firmware-idf/main/main.c`：让尚无 NVS 网络的设备也能初始化 Wi-Fi 并扫描；异步处理扫描、连接与事件结果；连接成功后写 NVS，失败恢复旧配置；把 Mac HTTP 故障从 Wi-Fi 回退条件中移除。Mac 请求连接失败或收到非 200 响应时重查 `.local` 名字，但重查失败不清空上次已成功使用的 IP。
- 启用 LVGL 已有的 Source Han Sans SC 16 字体并仅在设置页使用，控制固件体积，不修改 Monitor 字体。保留现有 USB 串口配置作为恢复入口，NVS 键名和分区表保持兼容。
- Mac 服务 `mac/server.mjs` 不改变；不增加设备 IP 输入框、云端转发或公网接口。

## 验证与风险

- 构建固件并检查 factory 分区余量；检查 APP 页 Monitor 图标像素布局、点击区域和原有页面行为不变。验证键盘触摸、密码遮挡、中文 SSID 的实际显示、开放网络和受保护网络。
- 设备端验证首次无配置扫描、正确密码连接、错误密码后旧网恢复、断网重连、两条已保存网络的回退。观察连接和扫描期间 UI 不被阻塞。
- 通过 DHCP 更新 Mac 地址验证 `.local` 重新解析；分别验证 Mac 服务停止、mDNS 不可达、设备 Wi-Fi 断开时状态区分且不会因 HTTP 失败切网。
- 先完成代码和构建验证，再提供固件预览与设备刷写范围供确认。刷机保留 NVS，且不把任何 Wi-Fi 密码、设备备份或本机配置提交到公开仓库。
